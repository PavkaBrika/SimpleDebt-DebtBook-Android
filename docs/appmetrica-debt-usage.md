# Первый долг и повторное действие в AppMetrica

Оба магазина используют проект Debt Book (App ID `6392758`). AppMetrica фиксирует первый запуск автоматически как установку. Приложение добавляет по одному событию `first_debt_saved` при первом успешном ручном создании долга и `debt_action_on_later_day` при первом успешном создании ещё одного долга, записи возврата или установке либо изменении напоминания в более поздний календарный день. Приложение сравнивает локальные даты устройства в момент действий и передаёт имена событий без параметров. [Базовые события AppMetrica](https://appmetrica.yandex.ru/docs/ru/data-collection/basic-events).

Пример сохранён в отдельном проекте **Debt Book — тест аналитики** (App ID `6394279`). Отчёт считает устройства, допускает промежуточные события и шаги из разных сессий. [Тестовая воронка](https://appmetrica.yandex.ru/apps/reports/funnels?appId=6394279&funnel=375376&period=2026-10-27%3A2026-11-26).

## Настройка воронки

1. Откройте **Отчёты → Продукт → Воронки → Создать воронку**. Задайте шаги **Первый запуск** (условие **Установка**), **Первый сохранённый долг** (условие **Событие**, `first_debt_saved`) и **Действие в другой день** (условие **Событие**, `debt_action_on_later_day`). Имена пользовательских событий появляются в селекторе после того, как они поступят в AppMetrica. [Воронки AppMetrica](https://appmetrica.yandex.com/docs/ru/mobile-reports/funnels-report).
2. В детальных настройках разрешите **События между шагами** и выберите **Регистрация событий** из всех сессий за период. Для подсчёта выберите устройства, чтобы охватить установки без настроенных профилей. [Детальные настройки воронки](https://b2b.yandex.ru/adv/edu/materials/funnels).
3. После публикации сборки `4.6.6 (45)` ограничьте когорту пользовательскими фильтрами **Установка и её атрибуты → Дата установки** и **Версия приложения**. Выбирайте первые запуски в `4.6.6` и последующих версиях с обоими событиями. Используйте версию на момент установки. Период самого отчёта должен охватывать и первый запуск, и последующие события. [Сегменты AppMetrica](https://appmetrica.yandex.ru/docs/ru/mobile-reports/segmentation).

## Расчёт метрик

| Метрика | Числитель | Знаменатель |
| --- | --- | --- |
| Активация | Уникальные установки когорты с `first_debt_saved` к дате расчёта | Все уникальные новые установки когорты |
| Повторное использование за 30 календарных дней | Уникальные установки из знаменателя с `debt_action_on_later_day` в дни 1–30 включительно после первого долга | Уникальные установки когорты с `first_debt_saved`, у которых полностью закончился день 30 после первого долга |

В каждой строке показывайте числитель, знаменатель и долю. Днём 0 считается локальная календарная дата первого сохранения. Для повторного использования окно закрывается в начале дня 31. Дата, введённая в записи долга или в напоминании, не участвует в расчёте.

Отчёт «Воронки» показывает порядок шагов за выбранный период. Для расчёта окна от даты первого долга используйте Logs API.

1. Выгрузите установки за период когорты. Возьмите `installation_id`, `install_timestamp`, `app_version_name` и `is_reattribution`. Оставьте первые запуски на `4.6.6` и последующих выпущенных версиях с обоими событиями. Исключите реатрибуции. [Logs API для установок](https://appmetrica.yandex.ru/docs/ru/mobile-api/logs/ref/installations).
2. Выгрузите оба события с начала периода когорты до даты расчёта. Для каждого события используйте `installation_id`, `event_name` и `event_timestamp`. Выберите время на устройстве (`date_dimension=default`), чтобы поздняя доставка офлайн-события не меняла день действия. Соедините данные по `installation_id` и оставьте по одной строке на установку с самым ранним временем каждого события. Повторяйте выгрузку за недавние периоды, чтобы подхватить события, пришедшие с задержкой. [Logs API для событий](https://appmetrica.yandex.ru/docs/ru/mobile-api/logs/ref/events).
3. Для оценки повторного использования переведите обе метки времени в один часовой пояс отчёта. В знаменатель возьмите только установки, у которых завершился день 30 в этом поясе. В числитель включите повторные события с меткой времени от первого сохранения до конца дня 30, включая день 0 отчёта. Само событие подтверждает, что на устройстве наступил более поздний календарный день. Укажите часовой пояс и пометьте результат как оценку. Logs API не возвращает часовой пояс устройства на момент события, поэтому точно восстановить местную дату на границе 30-дневного окна по этим полям нельзя. [Период выгрузки из AppMetrica](https://appmetrica.yandex.ru/docs/ru/common/export).

## Разрезы

Начните с общей когорты. После накопления данных добавьте два разреза.

- **Google Play / RuStore.** В AppMetrica примените фильтр по **App Installer** на момент установки. Google Play соответствует `com.android.vending`, RuStore соответствует `ru.vk.store`. Установки с неизвестным или системным установщиком показывайте отдельно. Поля установщика в стандартной выгрузке нет, поэтому по ней можно посчитать общую 30-дневную оценку, а статистику по магазинам сверять в воронке за указанный период. [Текущие отчёты по установкам](appmetrica-acquisition.md). [Группировки User Acquisition](https://appmetrica.yandex.ru/docs/ru/mobile-reports/user-acquisition-report#groupings).
- **Директ / органика.** В отчёте выберите партнёра **Yandex.Direct** или тип атрибуции **Органика**. Для расчёта по выгрузке добавьте `publisher_name`, `publisher_id` и `tracking_id` к полям установки. Для Директа используйте партнёра `Yandex.Direct` и сверяйте трекеры, для органики используйте `publisher_id = 0`. [Выгрузка данных AppMetrica](https://appmetrica.yandex.ru/docs/ru/common/export).
