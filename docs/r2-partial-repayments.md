# R2.1: явный частичный возврат

База: `codex/r1b-data-reliability` / `53ddc53` (включает R1a); рабочая ветка `codex/r2-partial-repayments`. На старте проверен origin: `origin/develop_main` / `e433a1c` является предком выбранной базы. Незакоммиченное уточнение приоритетов плана сохранено отдельным коммитом.

## Связь с долгом и балансом

История человека до R2 — независимые знаковые операции, а не список займов с установленными связями. Плюс означает «мне должны», минус — «я должен». Новое действие выбирает конкретную ненулевую исходную запись. Возврат хранится в Debt отдельной строкой с `repaymentOfId`, противоположным знаком и уникальным `operationId`. Остаток этой записи = модуль исходной суммы − модули действующих связанных возвратов. Общий баланс человека = `openingAdjustment` + сумма действующих операций со знаками. Эти два остатка могут различаться при встречных долгах и старой начальной поправке. Взаимозачет пользователь делает осознанно; приложение его не угадывает. Начальная поправка не становится займом автоматически. Если сохранился только баланс без исходной записи, для него нет достоверной связи возврата; отдельная ручная сверка таких старых данных в R2.1 не реализована.

Несколько возвратов допустимы до нулевого остатка включительно. Превышение отклоняется целиком. Отмена помечает возврат `cancelled`, сохраняет сумму, связь и идентификатор попытки, исключает его из баланса и снова открывает остаток. Редактирование возврата заменено отменой и созданием нового. Сумму/человека исходной записи со связанными возвратами менять нельзя; удалить такую запись нельзя даже после отмены всех возвратов. Удаление человека по прежнему удаляет всю его историю.

## Данные и совместимость

Все расчеты остаются BigDecimal. Полное погашение старой суммы с избыточными дробными знаками допускает точный остаток без округления; остальные новые суммы следуют правилам валюты R1b. Проверка актуального остатка, запись строки и пересчет баланса выполняются одной Room-транзакцией. Повтор запроса с тем же идентификатором не добавляет строку, включая повтор после отмены; повтор с другой суммой отклоняется. Ошибка изменения баланса откатывает также вставку/отмену возврата.

Миграция 16→17 добавляет nullable-связь/идентификатор и `cancelled = false`, индексы связи и уникального идентификатора. Старые строки, суммы, поправки, ID и даты сохраняются; никакие противоположные операции не объявляются возвратами.

Backup v3 содержит новые поля в существующей таблице debtList; число таблиц не меняется. Проверяются связи, направление, повторяющиеся идентификаторы, отмены, остатки и итог человека. Чтение v2 и старого плоского JSON сохраняется; их строки считаются независимыми. Подмена версии v3 на v2 отклоняется. Старый APK отвергнет v3 вместо потери смысла возвратов. Откат установки старого APK поверх Room 17 не поддерживается; перед обновлением нужна резервная копия. Фото и остальные разделы используют прежний переносимый контракт R1b.

Проверки, пользовательский сценарий и неподтвержденные пункты зафиксированы в [отчете R2.1](r2-verification-2026-11-16.md). Аналитика, сроки, уведомления, архив и публикация в этот пакет не входят.
