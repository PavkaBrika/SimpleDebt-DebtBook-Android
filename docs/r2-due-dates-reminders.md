# R2.2: срок возврата и личные напоминания

База `ce72c39`, ветка `codex/r2-due-dates-reminders`. Включены R2.1 и последующие исправления долгов, backup, PIN. Изменения владельца `.codex/skills/DRAFT!-developing-android-apps.md` остаются вне коммитов этапа; исходные index/worktree patches сохранены в `/tmp/debtbook-r22-owner-*.patch`.

## Правила до реализации

- Необязательный `dueDay` — строгая календарная дата ISO `yyyy-MM-dd`, только у конкретного ненулевого исходного долга. Старые записи получают NULL. Дата операции и суммы не меняются. Оба направления работают одинаково.
- Просрочка: местный календарный день устройства позже срока и остаток конкретного долга положителен. В день срока долг ещё не просрочен. У полностью погашенного долга срок сохраняется, просрочки нет.
- Напоминание владельцу однократное, в день срока в выбранное местное время (по умолчанию 09:00). Дата не сдвигается при поездке; время следует текущему часовому поясу устройства. Пропущенное при переходе DST время переносится вперёд системным Calendar, повторяющееся время имеет один системный instant; идентификатор предотвращает повторную доставку.
- Включить/изменить напоминание можно только на будущее. Прошедший срок допустим без напоминания. Изменение даты переносит включённое напоминание; если выбранное время уже прошло, нужно выключить функцию или выбрать будущее время/дату. Отключение удаляет ожидающее и показанное уведомление.
- Частичный возврат сохраняет напоминание для остатка. Полное погашение выключает его в той же транзакции. Отмена возврата открывает остаток, но не включает отключённое напоминание и не повторяет уже доставленное. Повторное включение — осознанное действие пользователя.
- Используется AlarmManager с неточным `setAndAllowWhileIdle`, без exact-alarm permission и foreground service. Доставка может задерживаться из-за Android/Doze/производителя. Отказ в POST_NOTIFICATIONS не блокирует учёт или сохранение срока; интерфейс объясняет отказ и даёт перейти в настройки. Запрос только при включении функции.
- Один PendingIntent и notification ID на исходный долг; перед доставкой повторно проверяются актуальная запись, остаток, token и разрешение. Факт попытки доставки хранится в БД до отправки, локальный журнал token предотвращает повтор при восстановлении старого backup на той же установке: сбой процесса в этот момент может пропустить уведомление, но не создаёт неожиданный повтор.
- Перезагрузка, обновление приложения, смена времени/часового пояса и возврат в приложение сверяют расписание с БД. Ещё не доставленное напоминание за сегодняшний день допускает позднюю доставку; более старое не воспроизводится. После force-stop Android блокирует фоновые события до ручного открытия приложения.
- Room 18 / backup v4 хранят срок, время, token и факт доставки. v2/v3/legacy читаются без автоматических сроков. Подмена номера формата с новыми полями отклоняется. Restore/undo отменяют прежнее расписание и показанные уведомления; восстанавливают только будущие, включённые, недоставленные напоминания при положительном остатке, без дублей. Прошедшие выключаются при восстановлении.
- Уведомление не содержит имени, суммы и заметок на экране блокировки. Открывает конкретную исходную запись через защищённую ReminderEntryActivity → MainActivity с существующим ActivityAuthGate; PIN нельзя заменить extras. Никаких сообщений должникам.

## Проверенные официальные требования Android

Проверено 16.11.2026: [POST_NOTIFICATIONS API33+](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [неточные alarms, отмена и перезагрузка](https://developer.android.com/develop/background-work/services/alarms). Exact alarm не требуется для выбранной доставки; точность до минуты не заявляется. Приёмка и фактические ограничения фиксируются отдельно в отчёте.
