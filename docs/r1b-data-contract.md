# R1b: правила данных

## Деньги

Единое представление во всех разделах — `BigDecimal`, в Room и backup — десятичная строка без экспоненты. Сложение/вычитание и итоговые суммы точные. Новая сумма: до 18 целых цифр; дробная часть по валюте (JPY — 0, остальные 28 доступных валют — 2; таблица также определяет валюты с 3/4 знаками). Лишние знаки отклоняются. Для явного округления — HALF_EVEN; миграция старых сумм не округляет и не стирает погрешности старого Double. Неизвестные старые валюты и исходные значения сохраняются.

Положительная операция долга означает «мне должны», отрицательная — «я должен». Валюты не складываются друг с другом. Итог человека = сохраненная начальная поправка + точная сумма операций. Для старых данных поправка = прежний итог − сумма прежней истории. Она сохраняет прежний видимый остаток при неполной/сомнительной истории; миграция не изобретает возвраты. Аналогично для накоплений цели. Создание/изменение/удаление и обновление итога происходят одной транзакцией; повторное удаление ничего не меняет. UI блокирует повторное сохранение до завершения операции.

## Даты

Новые календарные даты долгов — `yyyy-MM-dd`, без часового пояса. Известные старые текстовые даты распознаются строго по поддержанным языкам, исходная строка сохраняется. Неоднозначные числовые/неизвестные строки не угадываются и не скрываются; сортируются стабильно после распознанных дат. Время создания и старые Date других разделов остаются моментами epoch millis. Не выводить календарный день старого момента без явной зоны.

## Совместимость и восстановление

Миграции только вперед, без destructive fallback. После Room 15/16 установка старого APK не является rollback. Перед выпуском нужна копия старой базы; при ошибке миграции исходная база должна остаться пригодной для повторной попытки. Версия backup проверяется до замены, все ссылки/ID и обязательные поля валидируются; замена всех таблиц атомарная. Backup — ручное резервное копирование/восстановление, не синхронизация устройств. Фотографии требуют переноса содержимого: строка локального пути не является переносимой фотографией.

Источники: [BigDecimal, Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/math/BigDecimal.html), [миграции Room](https://developer.android.com/training/data-storage/room/migrating-db-versions). Фактические проверки и ограничения фиксируются отдельно в отчете R1b.

## Формат резервной копии v2

Оболочка `SimpleDebtBackup`, `formatVersion: 2`, `createdAt` (epoch millis), `recordCount`, `data`, `photos`. Суммы — канонические десятичные строки; Date — epoch millis. Все шесть таблиц обязательны. Проверяются типы, уникальные положительные ID, связи, исходные поправки/итоги, версия, размер, повторяющиеся JSON-поля; неизвестная версия/ошибка ничего не заменяет. Лимит файла — 32 Mi символов, фотографии — 6 MiB на файл; фото проверяется как изображение, переносится base64 и получает новый локальный путь. Пропавший исходный файл не изобретается. Старый JSON содержит только путь фотографии: изображение из него не восстанавливается.

Перед подтвержденным восстановлением полная пригодная копия нынешнего состояния сохраняется через AtomicFile в private noBackupFilesDir. Ошибка сохранения страховки отменяет замену базы. Откат операции доступен отдельной кнопкой; для переустановки нужно заранее экспортировать файл. Перед upload Drive предыдущий проверенный JSON копируется в отдельный Drive-файл. Фотографии не удаляются при неудачной записи базы; новые временные фото удаляются. Старые локальные фото автоматически не чистятся.

Старый Gson JSON не сохранял часовой пояс и миллисекунды в Date-строках. При импорте время читается в явно указанном на preview текущем поясе; неизвестные/неоднозначные форматы отклоняются. Исходный файл не перезаписывается; исходный текст календарных дат долга остается в legacyDate. Нельзя обещать восстановление информации, отсутствовавшей в старом формате.

## Валюта финансов и календарные даты (Room 16)

Финансовые записи теперь имеют собственную currency. Миграция 15→16 использует актуальную валюту финансов из настроек этой установки: прежний видимый смысл сумм сохраняется. Выбор валюты раздела фильтрует записи и агрегаты; сумма разных валют не выводится как один итог. Backup v2 содержит currency каждой записи. В старых JSON валюты финансов не было: preview явно показывает, какая текущая валюта будет применена; неизвестную первоначальную валюту восстановить из такого файла нельзя.

Новые выбранные даты финансов (calendarDay) и сроки целей (goalDay) — ISO-дни. Epoch Date оставлен как отдельное прежнее значение; у старых строк calendarDay/goalDay = null, миграция не выдумывает зону исходного события. Время создания/пополнений остается моментом. Срок с goalDay истекает после окончания выбранного календарного дня. [Material DatePicker использует UTC-день](https://developer.android.com/reference/kotlin/androidx/compose/material3/DatePickerState); преобразования в UI выполняются через LedgerDate, без трактовки UTC-полуночи как локального времени.

## Продолжение R2.1

В ветке `codex/r2-partial-repayments` контракт расширен до Room 17 / backup v3: возврат явно связан с исходной записью, отменённые возвраты сохраняются в истории и исключаются из итогов. Старые операции остаются независимыми; backup v2 и legacy читаются. Подробности — [контракт R2.1](r2-partial-repayments.md). Этот раздел не меняет зафиксированные результаты приемки прежнего R1b.
