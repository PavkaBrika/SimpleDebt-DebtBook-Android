# SimpleDebt 4.6.4 во внутреннем тестировании Google Play

Срез от 20 ноября 2026. База `6522b4b` ветки `codex/r2-due-dates-reminders` с правками проверки подписи и чтения старых дат. Play Console показывает рабочий выпуск **4.6.3 (41)** с `targetSdk 35`. В полном списке загруженных сборок максимальный `versionCode` — **41**. Кандидат **4.6.4 (42)** сохраняет пакет `com.breckneck.debtbook`, `minSdk 23` и использует `targetSdk 36`. [Все наборы App Bundle](https://play.google.com/console/u/0/developers/8917781839803951802/app/4976215252514620032/bundle-explorer-selector).

## Подпись для загрузки

Соберите `app` → `release` через **Build → Generate Signed Bundle / APK → Android App Bundle** с существующим keystore. Введите пароль keystore, alias и пароль ключа в мастере. SHA-256 публичного сертификата **ключа загрузки** совпадает у скачанного из Console сертификата и исходного `41.aab`:

```text
81:8B:68:47:41:8A:B8:7D:97:F5:86:A4:0E:8E:70:0A:6A:06:DC:2B:55:BF:FE:70:DF:6D:D6:57:45:16:C1:E0
```

Сертификат опубликованного APK, предназначенный для обновления на устройстве, имеет SHA-256 `A3:9B:25:D5:5C:8D:D8:7C:DB:AC:D3:57:D2:19:DE:CE:94:AB:5F:8F:AD:62:8B:48:8D:A1:4F:0E:FF:E6:33:18`. Для обычного обновления используйте внутренний трек. Внутренний доступ к приложениям подписывает загруженные артефакты отдельным тестовым сертификатом. [Подписи приложения в Console](https://play.google.com/console/u/0/developers/8917781839803951802/app/4976215252514620032/keymanagement), [подпись для внутреннего доступа](https://support.google.com/googleplay/android-developer/answer/9844679).

Подпись AAB через параметры мастера и отказ при отсутствии ключа проверены на JDK 17. Задача `verifyReleaseSigning` также прошла на JBR установленной Android Studio. У локального `app/release/app-release.aab` подтверждён сертификат ключа загрузки. Этот AAB собран до правки дат. Для выпуска соберите новый AAB из текущего дерева. Предыдущий AAB прошёл `bundletool validate` и использует выравнивание 16 КБ для всех четырёх ABI. После правки пройдено 253 модульных теста, 19 инструментальных тестов Room и резервного копирования и выполнен `lintVitalRelease`.

## Что сохранилось при локальном обновлении

- Android 15, API 35. Установили APK 4.6.3 (41) из Google Play, скопированный с локальной тестовой подписью, и обновили его `adb install -r` до release APK 4.6.4 (42) из ветки. Содержимое опубликованного APK сверили без служебных данных подписи. Идентификатор приложения в Android и время первой установки совпали до и после обновления.
- SQLite: версия Room 14 → 18, `integrity_check` вернул `ok`, `foreign_key_check` не нашёл нарушений. Сверили поля и ID 705 карточек людей, 14 010 записей истории долгов обоих направлений, 13 категорий, 3 финансовых операций, 3 целей и 4 пополнений. Совпали денежные значения, валюты, даты, комментарии, связи, остатки и счётчики ID. Семь настроек сохранились. Фото цели и зашифрованный файл PIN совпали побайтово. Старый PIN открыл 4.6.4.
- При первом прогоне обнаружили, что исходный текст даты с суффиксом `y.` сохранялся, но выпадал из хронологической сортировки. Теперь даты с `y.`, `a`, `j.` и `г.` распознаются, а исходный текст остаётся в `legacyDate`. Двусмысленные строки остаются дословными. Повторили обновление на исходной базе 4.6.3 после правки.
- Android 16, API 36. Через интерфейс 4.6.3 добавили долг `UpgradeQA` на 123,45 USD. После локального обновления сверили сумму, валюту и историю через интерфейс 4.6.4. Восстановили 38 записей через системный выбор файла из тестовой копии в формате Drive 4.6.3. Отмена восстановления вернула исходный долг и остаток 123,45 USD. Проверки Drive выполнены с тестовым сервисом. Сетевой сценарий требует отдельного Google-аккаунта и приложения с подписью Google Play.

## Короткая проверка обновления и Drive

1. На выделенном устройстве Android установите рабочую 4.6.3 (41) до подключения к внутреннему тесту. На эмуляторе `SimpleDebtPlay_API36` уже установлена опубликованная 4.6.3 из Console и создан долг `PlayQAAlice` на 100 USD. Для проверки обоих направлений добавьте второй тестовый долг на 80 USD. Зафиксируйте остатки и историю.
2. В 4.6.3 откройте **Settings → Synchronization → Authorization → Sign in with Google**, войдите в отдельный тестовый Google-аккаунт и сохраните копию в Drive. На `SimpleDebtPlay_API36` открыта форма входа Google. Убедитесь, что приложение показало успешное сохранение и дату.
3. Когда владелец отдельно запустит внутренний трек, подключите тестовый аккаунт по ссылке трека и обновите приложение через Play Store поверх 4.6.3 без удаления. Проверьте версию 4.6.4 (42), людей, остатки и историю. У старых долгов сроки должны быть пустыми. Проверьте частичный возврат и задайте будущий срок с напоминанием.
4. В 4.6.4 откройте **Настройки → Резервные копии → Восстановить из Google Drive**. Проверьте предпросмотр копии 4.6.3, восстановите её на тестовых данных и сверьте остатки и историю. Затем снова задайте будущий срок с напоминанием, сохраните новую копию, измените тестовую запись и восстановите новую копию. Должны вернуться остаток, срок и состояние напоминания.

## Выплаты за отключение рекламы

В аккаунте разработчика есть профиль **Google Play Apps** со страной «Россия». В разделе способа получения дохода Console предлагает добавить платёжный инструмент. Проверенного способа выплат сейчас нет. Google приостановил выплаты на счета российских банков, включая выручку от покупок из других стран. Чтобы подтвердить будущие выплаты, нужен допустимый платёжный профиль с поддерживаемым и проверенным способом получения дохода. Страна существующего профиля в Google Play не редактируется. [Платёжный профиль аккаунта](https://play.google.com/console/u/0/developers/8917781839803951802/paymentssettings), [ограничение для российских банков](https://support.google.com/googleplay/android-developer/answer/15685001), [смена страны профиля Google Play](https://support.google.com/googleplay/android-developer/answer/7162811).
