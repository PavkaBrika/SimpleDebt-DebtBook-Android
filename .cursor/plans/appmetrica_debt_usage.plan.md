# AppMetrica — первый сохранённый долг и повторное действие

Цель — понять, сколько новых пользователей Debt Book начинают вести долги и какая доля из них возвращается к этому сценарию в другой день. План охватывает два события в существующей интеграции AppMetrica для Google Play и RuStore.

## Что считать

| Событие | Условие |
| --- | --- |
| `first_debt_saved` | Один раз на новую установку после первого успешного ручного создания долга. Учитывать оба направления — «я должен» и «мне должны». |
| `debt_action_on_later_day` | Один раз на ту же установку после первого успешного действия в календарный день позже дня первого сохранения. Учитывать создание ещё одного долга, запись частичного или полного возврата, установку или изменение напоминания. Подходит действие с любым долгом. |

День действия — локальная дата устройства в момент успешной записи. Сравнивать дни выполнения действий, даже если пользователь внёс долг задним числом. Для отчёта брать установки, впервые запущенные в сборках с этими событиями. Под первым долгом понимается первая ручная запись на этой установке. Перенесённые и восстановленные записи сами по себе события не создают.

Передавать оба события по имени без параметров. Для расчёта достаточно факта действия и стандартных данных AppMetrica. Имена, контакты, суммы, заметки, даты и идентификаторы долгов остаются в приложении. [Пользовательские события Android SDK](https://appmetrica.yandex.ru/docs/ru/sdk/android/analytics/android-operations)

### 26 ноября 2026

- Ветка `codex/appmetrica-debt-usage` создана от локальной `develop_main` (`63be9c19`). Версия с событиями `4.6.6 (45)`. APK и AAB используют один release-вариант с общей активацией AppMetrica.
- Участие фиксируется при первом запуске release-версии с событиями. Файл настроек сохраняется при обновлении и исключён из Android Auto Backup и переноса. При восстановлении первая ручная запись на новой установке может начать отсчёт. Импорт и восстановление записей его не начинают.
- Повторное действие учитывается при более поздней локальной дате успешной записи. Повтор `operationId`, обычное редактирование, изменение только срока и отключение напоминания не учитываются. Включение либо изменение включённого напоминания учитывается по состоянию записи внутри транзакции. Состояние фиксируется перед вызовом SDK, который не подтверждает доставку, поэтому прерванная передача возможна без повторного вызова.
- Обновлены [политика конфиденциальности](../../docs/privacy_policy.html), [инструкция сборки](../../docs/release-build.md) и [отчёт по воронке](../../docs/appmetrica-debt-usage.md). Для 30-дневной метрики описана оценка по выгрузке с фиксированным часовым поясом отчёта. Logs API не отдаёт часовой пояс устройства на момент события.
