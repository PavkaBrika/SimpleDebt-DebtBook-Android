# Первый запуск в «Финансы → Расходы»

План реализации для следующего чата, 26 ноября 2026 года. Приложение позиционируется как карманный блокнот для повседневных денежных записей. На чистой установке пользователь должен сразу увидеть расходы и иметь возможность записать первую покупку. Переименование, иконка и материалы Google Play отложены на отдельный этап.

## Как должно работать

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть приложение с иконки впервые | После обычного входа видны «Финансы», выбраны «Расходы». Видна кнопка «Добавить расход», которая открывает форму расхода. |
| Посмотреть экран «Расходы» | Карточка с суммой расходов и кнопка «Добавить расход» оформлены в фирменной зелёной гамме. Выбранная вкладка «Расходы» и отрицательный «Итог за период» сохраняют терракотовый акцент. |
| Посмотреть нижнюю панель | Вкладки идут в порядке **Финансы → Долги → Цели → Настройки**. Подсветка соответствует открытому разделу. |
| Запустить с иконки после закрытия приложения или обновления | Открывается последняя сохранённая основная вкладка. Для обновления со старой версии без сохранённого ключа открываются «Долги», если в локальной книге есть карточки людей, включая закрытые долги. На чистой установке, при неизвестном ключе или при обновлении без карточек открываются «Финансы». «Настройки» не заменяют последнюю основную вкладку. |
| Вручную выбрать «Доходы», открыть операцию и вернуться, либо повернуть устройство | При восстановлении экрана остаются «Доходы». Для нового состояния финансов начальное значение — «Расходы». Расположение внутреннего переключателя прежнее: «Доходы» слева, «Расходы» справа. |
| Нажать «Назад» | Из формы — к её разделу, с другой основной вкладки — на корневые «Финансы», с корня — обычный системный выход. Повторное нажатие активной вкладки не добавляет экран в стек. |
| Открыть уведомление о долге | После проверки PIN, если она включена, открывается нужный долг в карточке человека. «Назад» возвращает к списку долгов, затем к «Финансам». |

## Шаги реализации

1. **Проверить исходную ветку.** На дату плана Compose-навигация есть в `develop_main` и в текущей ветке `codex/robokassa-ad-removal`. Перед правкой сверить рабочее дерево и перечисленные ниже места в актуальном коде. Пути к Kotlin-файлам ниже указаны относительно `app/src/main/java/com/breckneck/debtbook/`.
2. **Переставить основные вкладки и сменить корень навигации.** В `core/ui/components/BubbleBottomBar.kt` порядок задаёт список `barTabs`. В `core/navigation/DebtBookHost.kt` заменить корневой маршрут на `Finances` и согласовать с ним обе операции в `selectTab`: возврат на корень через `popBackStack` и переключение остальных вкладок через `popUpTo`. Сохранить восстановление состояния, выбор по стабильным ключам из `Routes.kt` и инициализацию сохранённой вкладки до показа первого экрана. Сейчас `core/MainActivity.kt` читает `last_tab` для обычного входа с иконки, а восстановлением уже открытого экрана занимается навигация.
3. **Открывать расходы по умолчанию.** В `finance/main/FinanceViewModel.kt` заменить начальное значение `INCOME` на `EXPENSE`, когда в `SavedStateHandle` отсутствует `direction`. В `finance/main/FinanceScreen.kt` страница уже выбирается через индекс направления и уже есть действие «Добавить расход». Проверить и пустой экран, и передачу направления в форму. Общий список `financeDirections` в `finance/FinanceComponents.kt` определяет расположение вкладок и направление свайпа также в форме.
   - Для `BubbleBalanceCard` на экране расходов использовать фирменную зелёную палитру `bubbleBalancePalette()` вместо отдельной бордовой палитры из `finance/main/FinanceSummaryChart.kt`. Цвета секторов диаграммы по-прежнему задаются категориями.
   - В `FinanceAddButton` использовать стандартные цвета основной кнопки `BubbleButton`. Это охватит закреплённую кнопку и её вариант внутри списка при малой высоте экрана. Терракотовый цвет выбранной вкладки в `FinanceDirection` и отрицательного итога в `finance/main/FinanceOverview.kt` берётся из общего `financeActionColors(EXPENSE)`; сохранить это значение.
4. **Проверить вход в долг из уведомления.** В `core/MainActivity.kt` метод `openReminderWhenUnlocked()` сейчас вызывает `popBackStack<Debts>()` перед открытием карточки. С новым корнем при холодном запуске списка долгов в стеке может ещё не быть. Обеспечить переход через «Долги» к нужной карточке при холодном и при повторном входе. В `debt/main/DebtRoutes.kt` есть обращения к записи `Debts` для результата выбора валюты и перехода после создания долга. Здесь список долгов остаётся родительским экраном. Проверить эти переходы отдельно от смены общего корня.
5. **Актуализировать проверки и описание поведения.** В `FinanceFlowTest` есть ожидание выбранных по умолчанию доходов, в `GoalsFlowTest` — проверки возврата на корень и восстановления через launcher, в `ReminderPinNavigationTest` — вход по уведомлению. Исправить ожидания для нового поведения, сохранив проверки выбора доходов, свайпов и возврата. В тестах долгов с явной предпосылкой «открыт список долгов» переходить туда через панель. Точечно обновить [описание запуска](../docs/APP_CORE.md) и [описание финансов](../docs/APP_FINANCE_FEATURE.md).

## Приёмка

- На выделенном тестовом устройстве выполнить чистую установку и открыть приложение **с иконки**. Проверить порядок и подсветку вкладок, создать первый расход через видимую кнопку, сохранить и увидеть его в своей категории. Перейти на «Доходы» нажатием и вернуться на «Расходы» свайпом.
- После первой траты за период без доходов осмотреть экран в светлой и тёмной темах. Карточка суммы и кнопка «Добавить расход» должны быть зелёными, выбранная вкладка «Расходы» и сумма со знаком минус в блоке «Итог за период» — терракотовыми. На экране малой высоты проверить зелёную кнопку внутри списка.
- Проверить возврат из формы, смену вкладок, системную кнопку «Назад» и восстановление экрана после поворота. Отдельно выбрать «Доходы» и воспроизвести восстановление задачи после завершения процесса системой.
- Проверить совместимость с обновлением: в предыдущей сборке выбрать «Долги», установить новую поверх с той же подписью и открыть с иконки. Ожидаются «Долги». Повторить обычный запуск после выбора «Целей» и посещения «Настроек» — ожидаются «Цели».
- Открыть реальное тестовое напоминание с включённым PIN из закрытого и из открытого приложения. Проверить нужный долг, возврат к списку и работу обычного запуска с иконки отдельно от уведомления.
- Собрать debug-приложение, запустить относящиеся к правке тесты и записать фактические результаты. Для Android-проверок сначала посмотреть установленные AVD, ориентиры — минимальная поддерживаемая версия (сейчас API 23) и актуальная стабильная. Операции с тестовыми данными выполнять на выделенном устройстве. Временный AVD из установленного образа после проверки остановить и удалить вместе с файлами. Загрузка дополнительного системного образа требует явного согласия владельца с указанием образа, цели и известного размера.
