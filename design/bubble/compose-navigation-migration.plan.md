# Полный переход Android-приложения на Compose

Исходная точка — `design/fix-design`, коммит `9bb62652`. Все 18 экранов основного графа, вход по PIN и восстановление PIN уже отрисовываются в Compose. Лист переименования удалён. Редактирование имени и фото доступно в карточке человека. В рабочем UI XML ещё загружает контейнер навигации и рекламный баннер через `activity_main.xml` и `view_ad_banner.xml`. Часть устаревших разметок ещё упоминается в адаптерах и ссылках для предпросмотра. [Основное окно](../../app/src/main/java/com/breckneck/debtbook/core/MainActivity.kt) · [Граф](../../app/src/main/res/navigation/nav_graph.xml)

Цель — Compose-оболочка и Compose-навигация для существующих сценариев. Будущему переносу на Kotlin Multiplatform помогут переносимые маршруты и явные границы с Android SDK. В объём этого этапа входят UI и навигация Android. Схема БД, формат резервных копий, правила расчёта денег, модель монетизации и подключение iOS за пределами этапа.

Зафиксировать холодный запуск с заполненным списком, первое открытие карточки, быстрые переключения вкладок и отменённый жест «Назад». Использовать одинаковые данные и настройки анимации до и после. [Приёмка Bubble](bubble-compose-rollout.plan.md)
- [ ] Сверить фактические аргументы, результаты и побочные эффекты по `nav_graph.xml`, вызовам `navigate`, каждому `*Fragment.kt` и чтениям `SavedStateHandle`. Часть аргументов, включая `openDebtId` из уведомления и параметры правки долга, объявлена в Kotlin. Учесть, где обновление происходит при каждом возврате, где нужен одноразовый результат, а где один результат обновляет несколько вкладок.

## 2. Подготовить типизированные маршруты

- [ ] Использовать уже подключённый Navigation Compose `2.9.7`, `rememberNavController`, `NavHost` и `@Serializable` маршруты. Подключить плагин Kotlin Serialization той же версии, что и Kotlin проекта. Эта версия Navigation поддерживает предиктивный возврат и восстановление стеков. У JetBrains есть версия того же Compose Navigation API для `commonMain`. Это позволяет сейчас сохранить механику текущего `NavController` при переходе на Compose. [Типизированные маршруты](https://developer.android.com/guide/navigation/design/type-safety) · [Несколько стеков](https://developer.android.com/guide/navigation/backstack/multi-back-stacks) · [Compose Multiplatform Navigation](https://kotlinlang.org/docs/multiplatform/compose-navigation-routing.html)
- [ ] Маршруты содержат ID и простые параметры, сериализуемые без Android-типов. Суммы, которые нужны в аргументах, передавать десятичной строкой без потери точности. Для редактирования цели и операции загружать запись по ID через имеющиеся репозитории или use cases. Обработать удалённую запись и сохранить введённый черновик при возврате, повороте и восстановлении процесса. Проверить ключи аргументов при переносе чтений на `SavedStateHandle.toRoute()`.
- [ ] Получать Hilt ViewModel на уровне записи стека. Разрешения, запуск системных окон и навигацию держать в composable маршрута или Android-хосте. Передавать экрану события через callback. Заменить привязку `BubbleBottomBar` к `R.id.*Fragment` на типизированные вкладки. Сохранить область жизни `MainViewModel` на уровне Activity.
- [ ] Передавать одноразовый результат в `SavedStateHandle` конкретной записи-получателя и потреблять его при возвращении на экран. Отмена закрывает маршрут без результата. Общие обновления после восстановления копии доставлять активным и сохранённым вкладкам через общее состояние или существующий механизм обновления данных. Проверить повторный вход в тот же экран и отсутствие повторной обработки результата после пересоздания. [Руководство по миграции с фрагментов](https://developer.android.com/develop/ui/compose/migrate/migration-scenarios/navigation)

| Маршруты | Что перенести вместе с экраном |
| --- | --- |
| Долги, форма долга, карточка человека, редактирование человека | После создания долга из списка открывается карточка с возвратом к списку. Сохранение из карточки возвращает в неё и обновляет историю. Сохранить редактирование, частичный возврат и отмену, открытие нужной записи по `openDebtId`, фото и выбор контакта. |

| Цели, форма цели, карточка цели | Правка из списка и карточки возвращает к источнику. Обе поверхности обновляются после записи, а удаление из карточки возвращает в список. Сохранить выбор фото и результат сохранения. |

| Настройки, валюта по умолчанию, оформление, защита, управление PIN, резервная копия | Сохранить возврат и применение темы, сценарии изменения PIN и биометрии, результаты экспорта и импорта, Google Drive, блокировку выхода во время операции и обновление затронутых списков. |

## 3. Переключить оболочку и навигацию

- [ ] Подготовить маршруты по разделам, затем переключить основной вход одним согласованным изменением. В `MainActivity.setContent` собрать `DebtBookTheme`, `NavHost`, общую нижнюю панель, лист оценки и слот баннера. Сохранить `ActivityAuthGate`, ручную настройку темы, обработку `onNewIntent` и завершение системных picker-сценариев. Уведомление должно дождаться готовности графа и разблокировки, открыть конкретную запись один раз и корректно обработать удалённый долг. Внешний вход и условия разблокировки сверить с текущей реализацией.
- [ ] Сделать текущую запись стека источником выбора вкладки. Сохранить `last_tab` и значения `debts`, `finances`, `goals`, выбор последней рабочей вкладки при холодном запуске из лаунчера и возврат к «Долгам» с других корневых вкладок. Сохранить прокрутку, период и валюту через сохранение и восстановление состояния. Быстрые повторные нажатия открывают один экран. Панель видна на корне и скрывается в поиске и на вложенных экранах.
- [ ] Единообразно применить системные отступы и высоту нижних элементов. Проверить клавиатуру, вырезы, три кнопки навигации, жестовую панель, отсутствие двойного отступа и положение кнопок при появлении баннера. Перенести характер переходов через Compose `enterTransition`, `exitTransition`, `popEnterTransition` и `popExitTransition`. Проверить первый кадр после заставки, отмену предиктивного жеста, выход домой с корня и масштаб анимации 0×. Ограничить обработчики «Назад» активным экраном и его локальным состоянием, например открытым поиском. [Предиктивный возврат в Compose](https://developer.android.com/develop/ui/compose/system/predictive-back-setup)

## 4. Подключить официальный Compose API Яндекса

- [ ] Добавить `com.yandex.android:mobileads-compose:8.6.0` к существующему `com.yandex.android:mobileads:8.6.0`. Сверить разрешённые версии и итоговый manifest. Для баннера использовать `Banner`, `rememberBannerAdState`, `BannerSize.Sticky` и `BannerEvents`. Сам SDK встраивает рекламный View. Убрать `ViewStub`, `view_ad_banner.xml` и неиспользуемую локальную обёртку `AdBannerComposable` после подключения. [Sticky-баннер Jetpack Compose](https://ads.yandex.com/helpcenter/ru/dev/android/compose/adaptive-sticky-banner) · [Артефакт 8.6.0](https://repo.maven.apache.org/maven2/com/yandex/android/mobileads-compose/8.6.0/)
- [ ] Создать одно состояние на слот в оболочке. Брать фактическую ширину с учётом безопасных зон. Запускать `loadAd` после инициализации и получения ширины. Переключение вкладки и рекомпозиция с прежними параметрами не запускают новый запрос. Сохранять измеренную высоту слота в отступах панели. Проверить загрузку, ошибку, поворот, смену ширины и отключённую рекламу без пустого зазора.
- [ ] Сохранить текущие настройки согласия, аналитику, отключение рекламы и политику `InterstitialPolicy`. Для межстраничной рекламы доступен `rememberInterstitialAdLoader()`. Если переносить загрузчик в Compose, держать его на уровне оболочки и сохранить показ только по существующему событию перехода, включая ограничения по жизненному циклу, защите и листу оценки. Проверять рекламу на отдельной тестовой сборке с demo ID, включая `demo-banner-yandex`. [Compose API межстраничной рекламы](https://ads.yandex.com/helpcenter/en/dev/android/compose/interstitial)
- [ ] Оставить подключение рекламы в Android-части оболочки с возможностью передать слот в UI. При фактическом переходе на KMP можно заменить этот участок официальным `com.yandex.ads.multiplatform:mobileads-compose`, если подойдут его требования. Сейчас документация библиотеки указывает **minSdk 24** для Android, а приложение поддерживает **API 23**. Android-расширение позволяет сохранить API 23 в текущей миграции. Перенос самого приложения на KMP можно выполнить с Android-реализацией рекламы за той же границей. [Требования Yandex Ads для Compose Multiplatform](https://ads.yandex.com/helpcenter/en/dev/compose-multiplatform/quick-start) · [Sticky-баннер Compose Multiplatform](https://ads.yandex.com/helpcenter/en/dev/compose-multiplatform/adaptive-sticky-banner)

Будущий перенос ресурсов, Hilt и JVM-типов, в том числе `java.math.BigDecimal`, оценивать отдельно при принятии решения о KMP.
